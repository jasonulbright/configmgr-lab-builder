# Unattend templates

Reference XML and INI shapes the engine generates. Hand-editing
these is rarely the right answer (the helpers handle the parameter
binding) but having them in one place makes "what does the engine
produce?" a one-page lookup.

## Sysprep base-image Unattend.xml

Generated by `New-LabBaseUnattend`. Injected into
`<base-vhdx>:\Windows\Panther\Unattend.xml` before first boot. Drives
sysprep `/generalize /oobe /shutdown` so the resulting VHDX is a
clean multi-VM differencing parent.

```xml
<?xml version="1.0" encoding="utf-8"?>
<unattend xmlns="urn:schemas-microsoft-com:unattend">
  <settings pass="specialize">
    <component name="Microsoft-Windows-Shell-Setup" processorArchitecture="amd64" ...>
      <TimeZone>UTC</TimeZone>
    </component>
  </settings>
  <settings pass="oobeSystem">
    <component name="Microsoft-Windows-International-Core" ...>
      <InputLocale>en-US</InputLocale>
      <SystemLocale>en-US</SystemLocale>
      <UILanguage>en-US</UILanguage>
      <UserLocale>en-US</UserLocale>
    </component>
    <component name="Microsoft-Windows-Shell-Setup" ...>
      <OOBE>
        <HideEULAPage>true</HideEULAPage>
        <HideOEMRegistrationScreen>true</HideOEMRegistrationScreen>
        <HideOnlineAccountScreens>true</HideOnlineAccountScreens>
        <HideWirelessSetupInOOBE>true</HideWirelessSetupInOOBE>
        <NetworkLocation>Work</NetworkLocation>
        <ProtectYourPC>3</ProtectYourPC>
        <SkipMachineOOBE>true</SkipMachineOOBE>
        <SkipUserOOBE>true</SkipUserOOBE>
      </OOBE>
      <UserAccounts>
        <AdministratorPassword>
          <Value>P@ssw0rd!</Value>
          <PlainText>true</PlainText>
        </AdministratorPassword>
      </UserAccounts>
      <AutoLogon>
        <Enabled>true</Enabled>
        <Username>Administrator</Username>
        <LogonCount>1</LogonCount>
        <Password>
          <Value>P@ssw0rd!</Value>
          <PlainText>true</PlainText>
        </Password>
      </AutoLogon>
      <FirstLogonCommands>
        <SynchronousCommand wcm:action="add">
          <Order>1</Order>
          <Description>Sysprep generalize and shutdown for base image</Description>
          <CommandLine>cmd /c %SystemRoot%\System32\Sysprep\sysprep.exe /generalize /oobe /shutdown /quiet</CommandLine>
          <RequiresUserInput>false</RequiresUserInput>
        </SynchronousCommand>
      </FirstLogonCommands>
    </component>
  </settings>
</unattend>
```

Encoding: **UTF-8 with BOM**. Windows Setup rejects no-BOM UTF-8
in unattend.xml.

## Per-VM Unattend.xml

Generated by `New-Unattend`. Injected into each per-VM differencing
VHDX before first boot. Sets ComputerName, static IPv4 + gateway +
DNS on the lab NIC (identified by MAC), local Administrator
password, optional AutoLogon. Domain join happens later via
`Add-Computer` over WinRM.

```xml
<?xml version="1.0" encoding="utf-8"?>
<unattend xmlns="urn:schemas-microsoft-com:unattend">
  <settings pass="specialize">
    <component name="Microsoft-Windows-Shell-Setup" ...>
      <ComputerName>CM01</ComputerName>
      <TimeZone>UTC</TimeZone>
    </component>
    <component name="Microsoft-Windows-TCPIP" ...>
      <Interfaces>
        <Interface wcm:action="add">
          <Identifier>00-15-5D-AB-50-20</Identifier>
          <Ipv4Settings>
            <DhcpEnabled>false</DhcpEnabled>
            <RouterDiscoveryEnabled>false</RouterDiscoveryEnabled>
            <Metric>10</Metric>
          </Ipv4Settings>
          <UnicastIpAddresses>
            <IpAddress wcm:action="add" wcm:keyValue="1">192.168.50.20/24</IpAddress>
          </UnicastIpAddresses>
          <Routes>
            <Route wcm:action="add">
              <Identifier>0</Identifier>
              <Prefix>0.0.0.0/0</Prefix>
              <NextHopAddress>192.168.50.1</NextHopAddress>
              <Metric>10</Metric>
            </Route>
          </Routes>
        </Interface>
      </Interfaces>
    </component>
    <component name="Microsoft-Windows-DNS-Client" ...>
      <Interfaces>
        <Interface wcm:action="add">
          <Identifier>00-15-5D-AB-50-20</Identifier>
          <DNSServerSearchOrder>
            <IpAddress wcm:action="add" wcm:keyValue="1">192.168.50.10</IpAddress>
          </DNSServerSearchOrder>
          <DisableDynamicUpdate>false</DisableDynamicUpdate>
          <EnableAdapterDomainNameRegistration>true</EnableAdapterDomainNameRegistration>
        </Interface>
      </Interfaces>
    </component>
  </settings>
  <settings pass="oobeSystem">
    <component name="Microsoft-Windows-International-Core" ...>
      <InputLocale>en-US</InputLocale>
      ...
    </component>
    <component name="Microsoft-Windows-Shell-Setup" ...>
      <OOBE>
        <HideEULAPage>true</HideEULAPage>
        <SkipMachineOOBE>true</SkipMachineOOBE>
        <SkipUserOOBE>true</SkipUserOOBE>
        ...
      </OOBE>
      <UserAccounts>
        <AdministratorPassword>
          <Value>P@ssw0rd!</Value>
          <PlainText>true</PlainText>
        </AdministratorPassword>
      </UserAccounts>
      <AutoLogon>
        <Enabled>true</Enabled>
        <Username>Administrator</Username>
        <LogonCount>5</LogonCount>
        <Password>
          <Value>P@ssw0rd!</Value>
          <PlainText>true</PlainText>
        </Password>
      </AutoLogon>
    </component>
  </settings>
</unattend>
```

Identifier in the TCPIP and DNS-Client components is the
**dashed-MAC** form (`XX-XX-XX-XX-XX-XX`). `Format-LabMacAddress`
normalizes from any common input (plain hex, colon-separated,
dotted-quad).

## SQL Server 2022 ConfigurationFile.ini

Generated by `New-LabSqlConfigIni`. Driven by
`setup.exe /CONFIGURATIONFILE=...`.

```ini
[OPTIONS]
ACTION = Install
QUIET = True
UPDATEENABLED = False
ENU = True
HELP = False
INDICATEPROGRESS = False
X86 = False
FEATURES = SQLENGINE
INSTANCENAME = MSSQLSERVER
INSTANCEID = MSSQLSERVER
INSTALLSHAREDDIR = C:\Program Files\Microsoft SQL Server
INSTALLSHAREDWOWDIR = C:\Program Files (x86)\Microsoft SQL Server
INSTANCEDIR = C:\Program Files\Microsoft SQL Server
AGTSVCSTARTUPTYPE = Automatic
COMMFABRICPORT = 0
COMMFABRICNETWORKLEVEL = 0
COMMFABRICENCRYPTIONLEVEL = 0
MATRIXCMBRICKCOMMPORT = 0
SQLSVCSTARTUPTYPE = Automatic
FILESTREAMLEVEL = 0
ENABLERANU = False
SQLCOLLATION = SQL_Latin1_General_CP1_CI_AS
SQLSVCACCOUNT = "NT Service\MSSQLSERVER"
SQLSVCINSTANTFILEINIT = True
SQLSYSADMINACCOUNTS = "BUILTIN\Administrators" "CONTOSO\Domain Admins" "CONTOSO\CM01$"
SECURITYMODE = SQL
SAPWD = "P@ssw0rd!"
INSTALLSQLDATADIR = "C:\Program Files\Microsoft SQL Server"
SQLUSERDBDIR = "D:\SQLData"
SQLUSERDBLOGDIR = "E:\SQLLogs"
SQLTEMPDBDIR = "D:\SQLTempDb"
SQLTEMPDBLOGDIR = "E:\SQLLogs"
SQLBACKUPDIR = "D:\SQLBackup"
ADDCURRENTUSERASSQLADMIN = False
TCPENABLED = 1
NPENABLED = 0
BROWSERSVCSTARTUPTYPE = Automatic
IACCEPTSQLSERVERLICENSETERMS = True
```

Encoding: **ASCII, no BOM**. SQL setup.exe rejects UTF-8 BOM.

Quoting: paths and accounts that contain spaces are wrapped in
`"..."` because setup.exe parses them as positional arguments
otherwise.

`SQLSYSADMINACCOUNTS` lists each principal as its own quoted
token, space-separated, in a single line. The CM site server's
computer account (`<NetBIOS>\<CMServer>$`) MUST be present so CM
setup can create CM_<SiteCode>.

```ini
SQLSSBPort = 4022

[CloudConnectorOptions]
CloudConnector = 0
CloudConnectorServer = CM01.contoso.com
UseProxy = 0
ProxyName =
ProxyPort =

[SystemCenterOptions]
SysCenterId =

[HierarchyExpansionOption]
```

Encoding: **ASCII, no BOM**.

`Preview = 1` is **omitted** entirely for `Branch = CB` (the
homelab default). It is only emitted for `Branch = TP`.

`PrerequisiteComp` is `0` when no offline cache is staged
(setup downloads its own); `1` when the CM-PreReqs cache has been
pushed to the VM.

`HierarchyExpansionOption` is empty for a primary site. Populated
only when adding a primary to an existing CAS.

## Why the helpers, not these templates

Hand-editing these files is brittle. Get one section header
wrong, one key misspelled, one quote-wrap missed and setup.exe
fails 30 minutes into a deploy with a misleading error. The
helpers (`New-CMUnattendIni`, `New-LabSqlConfigIni`,
`New-Unattend`, `New-LabBaseUnattend`) are the supported entry
points; this document is for understanding what comes out the
other side.
